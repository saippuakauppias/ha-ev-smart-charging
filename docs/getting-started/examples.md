# Примеры настройки

## Вспомогательные элементы

Единственный необязательный helper — флаг «сессия начата автоматизацией».
Создаётся в **Настройки → Устройства и службы → Вспомогательные элементы →
Создать → Переключатель**.

Он нужен, если вы иногда ставите машину на зарядку вручную днём и не хотите,
чтобы наступление конца окна её прервало. Без него блюпринт считает
своей любую активную сессию.

## Уведомления в Telegram

### Старт

```yaml
- action: notify.telegram
  data:
    message: >-
      🔌 Зарядка началась: {{ desired_current }} А,
      {{ soc if soc_valid else '?' }} % → цель.
      Нужно {{ needed_kwh | round(1) }} кВт·ч за {{ hours_left }} ч.
      {{ '❄️ Режим мороза.' if cold_mode else '' }}
```

### Завершение

```yaml
- action: notify.telegram
  data:
    message: >-
      {% set reasons = {
        'target_reached': '✅ Цель достигнута',
        'charger_reports_charged': '✅ Станция сообщила о завершении',
        'window_end': '🕒 Окно закончилось',
        'car_not_home': '🚗 Машина уехала',
        'unplugged': '🔌 Кабель отключён',
        'status_unknown': '❓ Статус станции нечитаем',
        'fault': '⚠️ Неисправность станции'
      } %}
      {{ reasons.get(stop_reason, stop_reason) }}.
      Заряд {{ soc if soc_valid else 'н/д' }} %.
      {{ '⚠️ Цель не достигнута.' if target_missed else '' }}
```

### Неисправность

```yaml
- action: notify.telegram
  data:
    message: >-
      {% set problems = {
        'switch_entity_missing':
          '🔧 Выключатель станции не найден — проверьте сущность в настройках',
        'charger_fault': '⚠️ Станция сообщает о неисправности',
        'car_refused_charge': '🚗 Машина не берёт ток',
        'charger_reports_no_power_but_car_charging':
          '❓ Станция не видит нагрузки, машина считает что заряжается',
        'no_power_while_on': '⚡ Включено, но ток не идёт',
        'car_data_unavailable_check_integration_auth':
          '🔑 Нет данных о заряде — проверьте авторизацию интеграции',
        'car_data_stale': '📡 Машина давно не выходила на связь',
        'car_data_frozen': '🧊 Процент заряда не меняется, хотя ток идёт'
      } %}
      {{ problems.get(alarm_reason, alarm_reason) }}
```

Об одном стоит знать заранее: **повторы блюпринт не гасит**. Пока проблема
держится, хук ошибки вызывается на каждом пересчёте — за долгую сессию это до полутора
десятков одинаковых сообщений. Ограничение только одно: о проблемах с данными
блюпринт молчит вне активной сессии, чтобы не будить вас, пока машина просто
стоит.

Гасить повторы нужно в самом действии уведомления. Проще всего — через
`notify` с одинаковым `tag`: телефон заменит предыдущее сообщение вместо того,
чтобы копить их стопкой.

```yaml
action: notify.mobile_app_phone
data:
  message: "Зарядка EV: {{ alarm_reason }}"
  data:
    tag: ev-charging-alarm    # каждое следующее заменяет предыдущее
```

Если уведомления нужны редкими, а не заменяемыми, добавьте перед хуком
собственное условие — например, `input_datetime` с временем последней отправки.

Почему подавление повторов не встроено в сам блюпринт — разобрано
в [идеях на будущее](../ideas.md#подавление-повторных-уведомлений-о-проблемах-с-данными).
Полные списки значений `stop_reason` и `alarm_reason` — на странице
[«Уведомления»](../guide/notifications.md).

## Типовые конфигурации

### Двухтарифный счётчик, заряд до 80 % в будни

| Параметр | Значение |
|---|---|
| Время старта / окончания | по данным энергосбытовой организации |
| Дни недели | пн–пт |
| Целевой заряд | 80 % |
| Резерв времени | 30 мин |
| Выключать в конце окна | включено |

### Без интеграции с автомобилем

Заполните только сенсор энергии сессии станции и целевую энергию. Растяжка
будет работать по счётчику станции.

| Параметр | Значение |
|---|---|
| Сенсор процента заряда | пусто |
| Сенсор энергии сессии | `sensor.<станция>_last_charge` |
| Целевая энергия сессии | нужные кВт·ч плюс ~14 % на потери |

### Слабая сеть

| Параметр | Значение |
|---|---|
| Максимальный ток | по самому слабому звену цепи |
| Запасное напряжение | ваше типичное, а не 230 |
| КПД зарядки | 82–85 |

Защита от недопустимого напряжения — задача реле напряжения в щите.
Блюпринт этим намеренно не занимается: аппаратная защита срабатывает мгновенно
и не зависит от того, жив ли Home Assistant.
