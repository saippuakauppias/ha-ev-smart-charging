# Диагностика

Отлаживать автоматизацию, работающую без присмотра, тяжело по одной причине:
самый частый её исход —
не сделать ничего, и именно этот случай труднее всего объяснить постфактум.
Поэтому каждый пересчёт называет **причину своего решения** — переменная
`verdict`, одна строка человеческим языком:

```
станция офлайн
кабель не подключён
машина не дома
статус станции нечитаем, старт вслепую запрещён
зарядка начата вручную, не вмешиваемся
включено, но ток не идёт (no_power_while_on)
ток в норме, но данные о заряде ненадёжны (stale)
ток в норме, отличие меньше зоны нечувствительности
ток надо менять, но идёт пауза (43 с)
пишем ток 14.0 → 16.0 А
```

Причина всегда **первая по счёту** из действующих, а не любая из них: если
станция офлайн и машина не дома одновременно, названа будет офлайн-станция —
именно она объясняет молчание.

## Журнал

Включите параметр **«Записывать ход зарядки в журнал»**. После каждого
пересчёта в журнале (Logbook) сущности выключателя появляется строка,
начинающаяся с вердикта:

```
пишем ток 14.0 → 16.0 А | план=soc | заряд=47.0% (не менялся 12.0 мин) |
ёмкость 43.0 кВт·ч | нужно 25.9 кВт·ч за 330 мин | U=207 В (sensor) × 1 ф |
уставка 14.0 → 16.0 А (возраст 1801 с), по факту идёт 12.8 А |
статус=charging | машина заряжается: yes
```

Пересчёты, не приведшие к командам, тоже записываются:

```
Без действий: вне окна зарядки | выключатель=выкл, статус=available, заряд=47.0%, уставка 14.0 А
```

Журнал — то, что стоит включить на первые сессии: он переживает перезагрузку
и хранится столько же, сколько остальная история.
